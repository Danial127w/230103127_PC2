Conclusion
The experiments showed that parallel performance depends on workload distribution, memory access patterns, and process overhead. Strong scaling achieved its best speedup with seven processes. In the GEMM experiment, tile size 96 gave the best measured performance. Dynamic scheduling with chunk size 1 provided the lowest load imbalance. The results demonstrate that using all available CPU cores does not always guarantee the best performance.
Hardware-Based Diagnostic Answers
1. False sharing: The stride measurements did not show a clear boundary effect at 128 bytes. The results were relatively close across tested strides.
2. Strong scaling: Performance improved up to seven processes, then decreased slightly at eight because of additional overhead and resource contention.
3. Weak scaling: Efficiency decreased as the workload and process count increased.
4. Roofline: The measured bandwidth and compute performance provide an estimate of the system's memory and computational limits.
5. GEMM tiling: Tile size 96 performed best in this run. Larger tiles do not necessarily improve performance.
6. Scheduling: Dynamic chunk size 1 gave the lowest load imbalance, while contiguous static scheduling performed worst for this workload.
